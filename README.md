# Energytool AI Consultant

Начальный прототип консультанта: веб-чат, поиск по локально переданной базе знаний, вызов совместимого API модели и локальное сохранение демонстрационных заявок. Исходные материалы организаторов и секреты в репозиторий не включаются.

## Запуск

Скопируйте `.env.example` в `.env`. Задайте длинные случайные разные значения `POSTGRES_PASSWORD`, `ADMIN_TOKEN`, `REVIEWER_TOKEN`, `RATE_LIMIT_SALT`, а также `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` разрешённого организаторами API. Для пароля PostgreSQL в Compose используйте буквы и цифры: специальные символы в URL соединения требуют отдельного кодирования. Создайте каталог `data` и положите в него предоставленный архив `knowledge-base.zip`. Запустите `docker compose up --build` и откройте http://localhost:8000. Сначала зарегистрируйте, утвердите и активируйте БЗ по инструкции ниже. Без настроенного API или активной БЗ возвращается безопасный ответ. Используйте только вымышленные контакты: заявки сохраняются в PostgreSQL и не отправляются.

Локально: `python -m pip install -r requirements.txt`, `alembic upgrade head`, затем `uvicorn app.main:app --reload --no-proxy-headers`. Без `DATABASE_URL` используется SQLite `energytool.db`; переход на PostgreSQL не переносит существующие SQLite-данные автоматически. Тесты: `python -m pytest -q`. Для интеграционного теста PostgreSQL задайте `TEST_DATABASE_URL` и предварительно примените миграции к отдельной тестовой БД.

Заявка создаётся в два шага: форма готовит черновик и показывает нормализованные контакты вместе с выдержкой из последних сообщений пользователя; только после подтверждения показанных данных создаётся запись. Повтор подтверждения с тем же `Idempotency-Key` возвращает прежнюю заявку. Черновик действует 15 минут; отмена удаляет неподтверждённый черновик. Истёкшие черновики удаляются при следующей подготовке заявки в этой сессии — отдельной периодической очистки пока нет. Для проверки браузера установите `requirements-dev.txt`, выполните `playwright install chromium` и запустите тесты с `RUN_E2E=1`.

Сообщения используют заголовок `Idempotency-Key` и поле `session_version`: повтор того же запроса возвращает сохранённый ответ, а устаревшая версия или повторное использование ключа с другим содержимым вызывает 409. Версию можно получить через `GET /api/sessions/{id}`, историю — порциями через `GET /api/sessions/{id}/messages?after_id=...&limit=...`. `POST /api/sessions/{id}/close` закрывает диалог для новых сообщений и заявок, сохраняя историю. Клиент сохраняет ключ неуспешной отправки в текущей вкладке и повторяет тот же запрос после обрыва.

## Управление базой знаний

Откройте http://localhost:8000/admin и введите токен администратора для регистрации, утверждения, активации и отзыва версий. Токен остаётся только в поле страницы. Регистрация и активация не заменяют ручную проверку документов: перед утверждением необходимо проверить полноту и правомерность использования. Файлы хранятся по хешу в `KNOWLEDGE_DIR`; перед использованием проверяется целостность. Кэш эмбеддингов привязан к содержимому.

Те же действия доступны через API с заголовком `Authorization: Bearer <ADMIN_TOKEN>`: `POST /api/admin/knowledge/register` регистрирует копию `data/knowledge-base.zip` и возвращает её SHA-256; `POST /api/admin/knowledge/{sha256}/approve`, `/activate` и `/revoke` управляют версией.

`GET /api/admin/knowledge` доступен также токену reviewer; `GET /api/admin/sessions/{session_id}/messages` возвращает reviewer только роли и длины сообщений, а admin — их текст. Действия с версиями и просмотр истории записываются в аудит без текста сообщений. Это ограниченный ролевой доступ по общим токенам окружения, без персональных учётных записей, ротации или раздельного утверждения. Храните токены вне исходников и не предоставляйте их посетителям.

## Ограничения и состояние сервиса

API ограничивает тело запроса 16 КиБ и частоту запросов в минутном окне: создание сессий, отправка сообщений и административные запросы — по 30 на адрес и категорию, остальные API — 120. Счётчики общие для экземпляров с одной БД и одинаковым `RATE_LIMIT_SALT`; при недоступности БД API отвечает 503. Значения `X-Forwarded-For` не используются для определения клиента; контейнер запускает Uvicorn с `--no-proxy-headers`. За общим прокси лимит применяется к адресу прокси, поэтому для промышленного размещения потребуется безопасно настроенный доверенный прокси или внешний ограничитель. Превышение лимита возвращает 429 и `Retry-After`. Одновременно обрабатываются не более четырёх запросов чата на процесс, сверх лимита возвращается 503. Это не глобальный лимит при нескольких процессах.

`GET /health/live` проверяет доступность процесса; `GET /health/ready` дополнительно проверяет соединение с БД, наличие утверждённой активной БЗ и конфигурации API модели. Последний endpoint не проверяет доступность удалённой модели. Страницы используют CSP без встроенных скриптов, а API и страницы отдают запрет кэширования. Эти меры не заменяют TLS и аудит безопасности.

Для сетевых вызовов настроен общий расчётный бюджет 25 секунд с отдельными лимитами на эмбеддинги, реранкер, генерацию и проверку; если основание или проверка недоступны, возвращается безопасный ответ. Таймауты HTTP ограничивают ожидание сетевых операций, но не являются гарантированным SLA и не включают всё время CPU или ожидания блокировки сессии.

## Сабмит

Пример организаторов задаёт `DATA_DIR/questions.csv` (`id,question`) и `DATA_DIR/knowledge-base.zip` (Markdown/TXT), результат — `submission.csv` (`id,answer`). Адаптер также принимает перечисленные в примере альтернативные имена файлов. Запуск: `python solution.py`. Команда `python package_submission.py` создаёт ZIP из кода и зависимостей; база знаний, вопросы и ключи в архив не входят. Тест `tests/test_submission.py` распаковывает этот ZIP в чистый каталог и запускает его на синтетическом наборе. Перед финальной отправкой отдельно сверьте лимиты ресурсов, доступность внешней сети и скрытые ограничения платформы: демонстрационный пакет их не определяет.

## Офлайн-оценка поиска

Запустите `python -m evaluation.retrieval_eval`. Скрипт сравнивает извлечённые документы с ручной разметкой в `evaluation/gold_sources.json` и сохраняет диагностические ранги в `docs/retrieval-baseline.json`. Для диалоговых вопросов поиск использует последние пользовательские реплики, исключая реплики ассистента; полный диалог остаётся контекстом ответа. Baseline по 18 демонстрационным вопросам и 292 фрагментам: recall@1 0,67; recall@5 1,00; recall@10 1,00; MRR@10 0,79. Разметка и метрики учитывают только попадание ожидаемого документа, а не подтверждение конкретных утверждений. Они не доказывают answer correctness и не являются независимой экспертизой.

## Статус и ограничения

Это **не законченная и не промышленная система**. Поиск объединяет BM25 и эмбеддинги через reciprocal rank fusion и при доступности использует реранкер. При отказе эмбеддера или реранкера поиск продолжается по доступным каналам. Ответ проходит проверку структуры, точности цитат и чисел, а затем отдельный вызов модели проверяет соответствие каждого утверждения цитате; ошибка проверки приводит к отказу. `VERIFIER_MODEL` позволяет выбрать отдельную модель; по умолчанию используется генератор отдельным вызовом, поэтому проверка не является независимой. Модель-проверяющий тоже может ошибаться; детерминированной проверки единиц и условий пока нет. Нет политики разрешения конфликтов, персональной аутентификации и полноценной защиты от инъекций. Токен посетителя предоставляет доступ к своей истории. Не используйте сервис с настоящими персональными данными и не публикуйте его в Интернет. Целевые показатели ТЗ не измерены. Перед передачей БЗ внешнему API необходимо подтвердить разрешение владельца данных.

Конкурсный адаптер обрабатывает строки независимо. Передача истории в регламентном формате, если она требуется помимо CSV-примера, нуждается в уточнении. Необходимо выполнить оценку на размеченном наборе, adversarial и нагрузочные испытания, проверить лицензию и требования к архиву, подготовить презентацию и согласовать доступ жюри.
